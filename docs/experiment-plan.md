# Reproduction experiment plan

The user-supplied paper, Sections IV–V, specifies four within-subject conditions, three tasks, 20 participants, one trial per task-condition cell, a 120-second timeout, and a 3 cm target tolerance. The manuscript is not redistributed here. This repository is implementation work, not completed experimental replication. The [paper review](paper-review.md) identifies unresolved outcome denominators and statistical details that must be clarified before collecting a replication dataset.

## Conditions and current implementation boundary

| Condition | Required operational definition | Current status |
|---|---|---|
| Continuous markerless fusion | SuperPoint image matching, aligned depth, PnP/refinement, and accepted cross-camera factors throughout the trial, with confidence-gated commits | Earlier CPU profiles passed individual reaches (1.70/2.27 mm and 0.91/2.78 mm grounding/tool errors) but lost registration afterward. Native 1280×960 headset rendering with a frozen CUDA profile passed six fresh captures at two poses, 35 seconds of live rest health, a fixed-world center reach (2.16/4.51 mm), and 30 seconds of reached-pose health. The first five-target attempt failed before target 1 moved because registration expired during review. Capture-cadence and reliable-camera transport subsequently passed a 35-second idle check (109/109 estimates, 350/350 open gates). The fresh traversal also failed before motion: synchronous planning blocked joint-feedback handling while visual registration remained valid. The nonblocking fix passed 44 controller tests and a later partial run completed targets 1/2; target 3 was rejected before motion for timestamp quality while all 1507 observed gates stayed open. A tighter clock-sync rule passed 32 Unity tests and a later full targets 1→5 traversal: grounding 0.17–0.78 mm, tool 2.62–4.87 mm. It began at the previous target-2 pose, not neutral rest. The associated 150-second monitor passed 1516/1516 statuses and 453/453 estimates; final target-5 health passed 299/299 and 92/92 over 30 seconds. These overlapping bounded windows are reported separately. Earlier checked-return/interruption tests preserve recovery/freeze evidence. Changing headset viewpoints, dynamic tasks, physical capture and participant outcomes remain unvalidated. Known-alignment tests are separate. |
| One-shot ablation | Same initial markerless registration, inputs, planner, and feedback as continuous mode; reject all subsequent cross-camera factors, retain the initial mapping | Not shipped as an experimental condition. Implement a locked initial transform and log later observations without letting them update control. The stale-registration policy must be explicitly defined for this ablation so it can run rather than immediately time out. |
| Fiducial baseline | Calibrated ArUco-derived transform, identical inputs/planner/feedback, recorded marker visibility and occlusion | Not shipped. Requires known marker geometry, camera calibration, transform chain, and an explicit temporal update policy. Do not allow fiducial data into continuous or one-shot estimators. |
| Tablet-only baseline | Top-down workcell display and target selection, same planner/controller and target definition, no MR registration | Not shipped. Requires a target/scene view and calibrated pixel-to-workcell selection, with an explicit policy for moving targets. |

Quest 3S head direction replaces measured eye gaze, and the controller pointer replaces the paper's stylus unless a calibrated physical stylus is added. Use the same declared input modalities across all MR conditions. The deictic K1 task is fixed-base, four-joint **position-only** reaching: Unity derives a surface-normal orientation, but the reach planner does not solve that orientation. Do not score this as reproduction of the paper's approach-orientation behavior. The separate [bimanual pose teleoperation mode](arm-teleoperation.md) is an additional interaction capability, not one of the paper's conditions. Walking, balance control, grasping, and force contact are outside this protocol.

## Tasks

| Task | Paper protocol | Reproduction preparation |
|---|---|---|
| T1: static user | One reach to one of five tabletop targets from a fixed operator position | Five fixture targets exist; automated fixed-world center reaches were independently scored using the documented CPU and native-resolution CUDA profiles. Freeze the complete target/neutral-pose/board/operator-region protocol before repeated trials. The current demonstration is not a participant trial runner. |
| T2: mobile user | Four sequential reaches while changing viewpoints; neutral return between targets | Predefine viewpoint waypoints, target order, neutral-return completion, tracking-reset handling, and independent board/robot/headset ground truth. Preserve the same route distribution across conditions. |
| T3: dynamic scene | Move target objects and introduce an obstacle during a reach sequence; operator redirects | Obtain/define the missing reach count, timing, motion schedule, obstacle dimensions, and correction policy. Update real scene depth/geometry when objects move. A static scanned mesh alone is insufficient evidence of dynamic-target tracking. |

For simulated trials, keep scene geometry, camera paths, textures, noise, latencies, target sequence, and random seed fixed across matched conditions. Reserve simulator truth for scoring; exclude it from markerless observations and the control transform. Add low-texture, occlusion, fast-head-motion, and stale-message cases before user evaluation.

The current camera/matcher investigations are development experiments, not participant tasks or a scored replication dataset. Declare the development captures and ordered candidate settings before selection, freeze a setting using only geometric/confidence gates, then acquire distinct later validation frames. Preserve failed attempts and do not retune on heldouts. Truth-assisted epipolar or neighborhood-depth diagnostics can explain possible errors, but must remain isolated from estimation and cannot convert rejected observations into validation successes. The native-resolution profile has passed static, idle-health, individual-reach and one complete stationary-headset five-target traversal; these stages do not substitute for the paper's multi-viewpoint or dynamic tasks.

The engineering five-target test uses a stationary synthetic headset and sequential targets, starting later reaches from the prior measured pose. It does not implement T2's changing user viewpoints and neutral return. The first two attempts stopped before execution: first from stale registration, then from joint-feedback starvation during synchronous planning. The third completed targets 1 and 2, then rejected target 3 for a goal timestamp outside the backend window. After the clock correction, the **20:03:28–20:04:07 UTC traversal passed all five targets** in 39.176 seconds, including 4.5 seconds of preview review per target. It started from the prior target-2 pose, then reached 1→5. Independent grounding errors were 0.17–0.78 mm and measured tool errors 2.62–4.87 mm. Preserve this engineering result separately from the earlier failures and from a paper-protocol trial; its full run time is not paper task-completion time.

## Metrics and records

| Metric | Definition and required evidence |
|---|---|
| Alignment translation/rotation | Compare estimated `T_base_headsetWorld` to an independently measured truth at matched timestamps. Record the exact SE(3) difference convention; translation in meters and rotation angle in radians/degrees. Headset map resets require explicit segment handling. |
| Target-grounding error | Distance from intended target center to the Cartesian goal received by the robot, before execution. Keep separate from end-effector tracking and target-entry errors. |
| Task success | Every required reach enters 0.03 m of the target with no table/obstacle contact. Store each binary reach outcome and the binary all-reaches task outcome; do not substitute a percentage without a stated denominator. Reconcile the paper's success tables first. |
| Completion time | First committed command to final successful reach. Record cancellations, participant termination, and 120-second timeouts separately; prespecify whether/how incomplete trials enter time analysis. |
| Interventions | Count user cancellations and corrected target commits with unique event IDs. Distinguish rejected commits and automatic safety holds from operator corrections. |
| Workload/usability | Raw unweighted NASA-TLX and conventional SUS, preserving question wording and response anchors. Verify Performance scale direction before applying the paper's stated reversal. |
| Diagnostic metrics | Capture-to-registration/goal/actuation latency, frame skew, registration age, inlier count/ratio, reprojection residual, graph updates, rejected commits and reasons, tracking resets, packet loss, actual end-effector pose, and collision events. |

Record original RGB/depth/intrinsics and capture poses when consent and storage arrangements permit, robot joint states, estimated transforms, accepted/rejected registration observations, goal/execute/cancel events, trajectories, actual feedback, and independent truth. Store package/model commits, calibration hashes, scene/URDF version, parameters, device/OS/SDK versions, sensor providers, condition, participant/trial ID, clock offsets, and synthetic-versus-physical labels. The ROS topic interfaces make logging possible, but a complete scored trial manager and participant-data pipeline are not yet shipped.

## Analysis and completion criteria

Reconcile the paper's binary-success denominators, treatment of failed times, Task 3 schedule, and reported paired effect-size/p-value mismatch. Then freeze the protocol and analysis code before new data collection. Use participant-level repeated measures, balanced condition order and randomized task order, retain exclusions with reasons, and report uncertainty and appropriate binary/count models. A non-significant full-versus-fiducial difference is not evidence of equivalence.

Declare the architecture reproduced only after the actual camera-to-registration-to-fusion-to-goal-to-measured-execution loop passes, including failure/recovery behavior. Declare simulation validation separately from physical Quest/K1 validation. Declare numerical/behavioral replication only after an independently scored, properly authorized study; the paper's 49% grounding and 52% intervention improvements are comparison claims to test, not expected outputs or acceptance thresholds.
